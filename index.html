What I can help with

Each engagement starts from a problem, not a package. These are the ones I solve most often.

  • Websites for small businesses

    You need a site that explains what you do and makes it easy to call, book, or order. We design and build it by hand, so it loads fast and stays easy to change.

    • Single-page and multi-page sites
    • Menus, booking, contact forms
    • Mobile-first layouts

  • Website maintenance and fixes

    Your site mostly works, but a form fails, a page breaks on phones, or content is out of date. We find the cause, fix it, and tell you what changed.

    • Bug and layout fixes
    • Content and menu updates
    • WordPress edits

  • Technical support and troubleshooting

    Something in your software is failing and nobody can say why. We reproduce it, isolate the cause, and write down the fix so the next person can handle it faster.

    • Issue reproduction and root cause
    • Debugging and testing
    • Clear written handoffs

  • Installable web apps

    You want something people can add to their home screen and use like an app, without app-store overhead. We build progressive web apps in plain JavaScript.

    • Service workers and install prompts
    • Local data storage
    • Audio and media features

  • Small internal tools

    Your team repeats the same manual step every day. We build focused tools that remove it.

    • C# and ASP.NET MVC
    • SQL-backed workflows
    • Node.js utilities

  • Speed, accessibility and SEO cleanup

    Your pages are slow, hard to use with a keyboard, or invisible in search. We tidy the markup, structure, and assets so people and search engines can read them.

    • Semantic HTML and headings
    • Image and font loading
    • Metadata and structured data

How a project runs

Four steps, with a checkpoint at each one so nothing surprises you.

  1. Talk it through

    You describe the problem or the goal. We reply with questions before proposing anything.

  2. Agree on scope

    A short written plan: what gets built or fixed, what doesn't, and when.

  3. Build and review

    You see working pages early and often, tested on real phones and browsers.

  4. Launch and support

    We publish it, hand over notes on how it works, and stay available for fixes.
